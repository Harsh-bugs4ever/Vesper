# Frontend Phase 3 API dependencies and gaps

The Phase 3 screens call authenticated `GET /bookings/today?day=YYYY-MM-DD`, `GET /bookings`, `GET /stays?status=in_house`, `GET /rooms`, `GET /guests/{id}` when `guests:read` is granted, `GET /visits/{id}/profile`, and `POST /bookings/{id}/check-in` with `{ "room_id": "uuid" }` or `POST /stays/{id}/check-out`. They use `GET /tasks/mine`, `GET /tasks`, `GET /tasks/progress/{department_id}`, `PUT /tasks/{id}/status`, `POST /tasks/{id}/claim`, `PUT /tasks/{id}/assignee`, `GET /attendance/me`, `GET /attendance/team`, `POST /attendance/check-in`, `POST /attendance/check-out`, `POST /issues`, `GET /issues`, and `GET /maintenance/work-orders`. The backend must enforce property and department scope for each route.

Known backend blockers found during frontend implementation:

- `app/api/staff/router.py` references undefined `department_id` in `/tasks/mine` and undefined `scope` in `/tasks`. Both routes currently fail before returning records. The frontend displays the API error instead of sample tasks. The fix belongs in the backend phase.
- Even after that fix, `/tasks` filters Staff results to tasks already assigned to them, so the claimable pool cannot show unassigned tasks. A department-scoped claimable listing is needed, and `POST /tasks/{id}/claim` must permit an authorized Staff user to claim those unassigned tasks without exposing other departments.
- Front-office staff need `bookings:read` for the workspace and `bookings:write` for check-in/out. The backend's default Staff permissions currently omit both, so eligible front-office staff need backend-issued permissions. The frontend cannot grant them.
- Manager task assignment needs a list of eligible staff. `GET /admin/users?department_id=...` requires `users:read`, which default Manager permissions omit. Either grant a scoped read permission or add `GET /tasks/eligible-assignees?department_id=uuid` returning `[{"id":"uuid","full_name":"...","department_id":"uuid"}]` for an authorized manager. Until then, the assignee picker stays unavailable.
- Staff-report submission/review/approval endpoints are absent. Required: `POST /staff-reports` accepting `{ "department_id":"uuid", "summary":"...", "details":"..." }` and returning a persisted report with id/status/timestamps; `GET /staff-reports?department_id=uuid` returning only authorized reports; and `POST /staff-reports/{id}/approve` with an explicit approval outcome. These features remain unavailable in the UI.
- `GET /rooms` has status and category but no image URL. A room-detail response needs a nullable backend-owned `image_url` (or an authorized media endpoint) to render real room images. The UI labels imagery unavailable until that contract exists.
- Issue responses expose `room_number` and `asset_id` but no `room_id` or `work_order_id`. The UI can correlate an authorized work order by asset ID; an explicit nullable `work_order_id` and `room_id` would make the link reliable.

The local backend at `localhost:8000` did not respond during this frontend pass. End-to-end checks requiring login, mutation, reload and cross-department accounts could not be executed locally. No mock response or local success state was substituted.
